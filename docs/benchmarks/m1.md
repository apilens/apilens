# M1 ingest baseline (2026-10-22)

First measurement of the v2 edge (`-target=all`, direct sink, `ack=flush`) on
the self-host compose stack. It is a **smoke baseline, not a capacity
number**: everything ran on one laptop VM and the load generator competed for
the same CPUs.

## Setup

| | |
|---|---|
| Host | colima VM, 2 vCPU, 4 GB RAM (Apple silicon host) |
| Stack | `task e2e:up` (deploy/compose + ci overrides), single ClickHouse 26.8.33.10, Postgres 17.11, Valkey 9.1.2 |
| Sink | `batch_size=10000`, `flush_interval=100ms`, `ack=flush` (group commit: reply after the batch is stored) |
| Client | `tools/loadgen`, v1 JSON `/v1/requests`, 256-byte request + response payloads, same host |

## Results

| Offered rate | Batch | Concurrency | Records | Failed | Batch latency p50 / p95 / p99 | apilens CPU / RSS | ClickHouse CPU |
|---|---|---|---|---|---|---|---|
| 10,000/s | 200 | 16 | 250,000 | 0 | 132 / 179 / 188 ms | 11% / 17 MiB | 40% |
| 50,000/s | 500 | 32 | 1,000,000 | 0 | 133 / 178 / 186 ms | 26% / 50 MiB | 45% |

CPU percentages are of one core, sampled once mid-run with `docker stats`.
All 1,250,000 records were present in `api_requests`, and the
`api_requests_1m` rollup summed to the same total.

## Reading the numbers

- Latency is dominated by the group-commit window (100 ms) plus the insert:
  the edge deliberately waits for ClickHouse before answering so a 200 means
  "stored". `sink.ack=enqueue` trades that guarantee for single-digit-ms
  responses.
- At 50k records/s the edge used about a quarter of one core. The ceiling on
  this VM was not reached; the next measurement should run the load generator
  on a separate machine and push until `apilens_sink_rows_rejected_total`
  (backpressure, HTTP 503) starts counting.

## Reproduce

```sh
task e2e:up
KEY=$(docker compose --env-file deploy/compose/ci.env -f deploy/compose/compose.yaml \
  -f deploy/compose/compose.ci.yaml run --rm --no-deps --entrypoint /apilens apilens seed | jq -r .api_key)
task loadgen -- -key "$KEY" -app default -rate 50000 -batch 500 -concurrency 32 -duration 20s -payload 256
```
