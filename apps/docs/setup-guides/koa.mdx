<Warning>
The JavaScript SDK (`apilens-js-sdk`, v0.1.x) is **beta**. The Koa middleware is tested with Koa 3 and `@koa/router` 15 on Node 18+.
</Warning>

## Install

```bash
npm install apilens-js-sdk
```

## Add the middleware

```javascript
import Koa from "koa";
import Router from "@koa/router";
import { bodyParser } from "@koa/bodyparser";
import { apiLensKoa } from "apilens-js-sdk/koa";

const app = new Koa();
const router = new Router();

app.use(apiLensKoa({
  apiKey: process.env.APILENS_API_KEY,
  appId: "storefront-api",        // the app's slug from your APILens project
  environment: "production",
  routers: [router],              // optional: lists your routes in the app metadata
}));
app.use(bodyParser());            // after APILens, so request bodies are captured

router.get("/orders/:id", (ctx) => {
  ctx.body = { id: ctx.params.id };
});
app.use(router.routes());

app.listen(3000);
```

Mount the middleware **first**, before the body parser and your routers. It reads the response as Koa writes it (JSON, text and streamed bodies alike) and records the request once the response has been sent. Requests are grouped by the `@koa/router` route that matched (`ctx._matchedRoute`, router prefixes included), so `/orders/42` and `/orders/43` both count towards `/orders/{id}`. Requests no route matched are grouped by their path, with id-looking segments replaced.

`instrumentKoa(app, config)` mounts the same middleware and exposes the client as `app.context.apilensClient`.

## Identify consumers

Set the consumer on the context once your auth middleware knows who is calling:

```javascript
import { setConsumer } from "apilens-js-sdk/koa";

app.use(async (ctx, next) => {
  if (ctx.state.user) {
    setConsumer(ctx, { id: ctx.state.user.id, name: ctx.state.user.email, group: ctx.state.user.plan });
  }
  await next();
});
```

A string works too (`setConsumer(ctx, "acme-corp")`), or pass a centralized `getConsumer(ctx)` resolver in the config.

## Errors

An error thrown by a downstream middleware or route is kept for the request's ERROR log (with its stack) and rethrown unchanged, so Koa's own error handling still answers the request.

## Options

The middleware takes the same options as the [Express middleware](/setup-guides/express): delivery (`batchSize`, `flushIntervalMs`, `maxQueueSize`, …), header and body capture (`requestLogging`, `captureProfile`), redaction, exclusions, sampling and tracing. Every option can also be set with its `APILENS_*` environment variable.

## Capture posture

`captureProfile` picks what leaves the process in one word: `metadata` (no headers or bodies), `redacted` (headers and bodies with the default masking, 16 KB body cap) or `full` (the default). Every profile still sends the base record, so metrics and dashboards stay exact. For a first production rollout, start on `metadata`:

```javascript
app.use(apiLensKoa({
  apiKey: process.env.APILENS_API_KEY,
  appId: "storefront-api",
  captureProfile: "metadata",     // metadata | redacted | full
}));
```

An explicit option wins over the environment, so for a rollout leave the profile out of code and set `APILENS_CAPTURE_PROFILE` instead: the posture can then be widened or tightened with a redeploy. `metadata` still sends the URL with its query string, so add a `redactQueryParams` pattern for any parameter that carries personal data. See [Capture profiles](/getting-started/data-privacy#capture-profiles) and [phase 2 of the rollout guide](/guides/third-party-rollout#phase-2-capture-posture).

## Environment variables

Every option has an `APILENS_*` variable, with the Python SDK's names, so keys, posture and patterns stay out of code. A typical deployment:

```bash
APILENS_API_KEY=apilens_...          # project key, from your secret store
APILENS_APP_ID=storefront-api
APILENS_ENVIRONMENT=production
APILENS_CAPTURE_PROFILE=metadata     # metadata | redacted | full
APILENS_REDACT_QUERY_PARAMS=^email$,token
# Kill switch. Wins over code, in the direction that captures less:
# APILENS_CAPTURE_SPANS=false        # no spans or error-trace logs
```

Precedence is **explicit option > env var > default**. `APILENS_ENABLED=false` turns the SDK off on the next deploy, as long as `enabled` is not set in code ([SDK runbook](/guides/sdk-runbook#stop-capture-kill-switch)). The JavaScript SDK always sends the client IP in full: `APILENS_CAPTURE_IP` and `APILENS_ANONYMIZE_IP` are not read yet. The full list is in the SDK's [environment variable reference](https://github.com/apilens/apilens/blob/v2/packages/sdk-typescript/README.md#environment-variables).

## Shut down cleanly

Flush buffered records before the process exits:

```javascript
process.on("SIGTERM", async () => {
  await app.context.apilensClient?.handleShutdown({ flush: true });
  process.exit(0);
});
```

## Verify

Send a few requests and open the **Traffic** page — your Koa app's endpoints appear with their route templates alongside your other services in the project.
