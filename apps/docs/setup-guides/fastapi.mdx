## Install

```bash
pip install "apilenss[fastapi]"
```

<Info>
The PyPI distribution is `apilenss` (double *s*); the import package is `apilens`. Requires Python ≥ 3.10 and FastAPI ≥ 0.110.
</Info>

## Add the middleware

```python
import os
from fastapi import FastAPI
from apilens.fastapi import ApiLensMiddleware

app = FastAPI()
app.add_middleware(
    ApiLensMiddleware,
    api_key=os.environ["APILENS_API_KEY"],
    app_id="orders-api",          # your service's name; the app appears on first data
    env="production",             # default; use "staging", "development", ...
)
```

That's it for metrics, request logs, and traces. `api_key` is your **project-level** key (Settings → API keys); `app_id` attributes this service's traffic to the right app in the project.

<Tip>
When stacking multiple middlewares, add `ApiLensMiddleware` **last** so it wraps the full request lifecycle and its timings include your other middleware.
</Tip>

## Identify consumers

Report who is calling once your auth resolves the user — via a dependency or inside handlers:

<CodeGroup>
```python Dependency
from fastapi import Depends, Request
from apilens.fastapi import set_consumer

async def identify_consumer(request: Request, user=Depends(get_current_user)):
    set_consumer(request, identifier=user.id, name=user.name, group=user.plan)

app = FastAPI(dependencies=[Depends(identify_consumer)])
```

```python In the endpoint
from apilens.fastapi import set_consumer

@app.get("/orders")
async def list_orders(request: Request):
    set_consumer(request, identifier="acme-corp", group="premium")
    ...
```
</CodeGroup>

Alternatively pass a centralized resolver: `get_consumer=lambda scope, headers: ...` on the middleware. An explicit `set_consumer` always wins over the resolver.

## Tune capture

Headers and bodies are captured by default (sensitive headers redacted in-process). Common adjustments:

```python
app.add_middleware(
    ApiLensMiddleware,
    api_key=os.environ["APILENS_API_KEY"],
    app_id="orders-api",
    enable_request_logging=False,   # metrics + traces only
    log_response_body=False,        # or drop just one side
    max_payload_bytes=4096,         # tighter body cap (default 65536)
    capture_spans=False,            # disable tracing for this app
)
```

To keep capture on but strip PII, redact by name instead of turning things off — regexes match query parameter / header / JSON body field names, and matched values are stored as `[redacted]`:

```python
app.add_middleware(
    ApiLensMiddleware,
    api_key=os.environ["APILENS_API_KEY"],
    app_id="orders-api",
    redact_query_params=[r"^card_number$", r"token"],
    redact_headers=[r"^x-internal-secret$"],        # on top of the built-ins
    redact_body_fields=[r"^password$", r"^cvv$", r"card"],
)
```

The full option list — including `base_url`, TLS options, and env-var kill switches — is in the [Python configuration reference](/sdk-reference/python-configuration).

## Capture posture

`capture_profile` picks what leaves the process in one word: `metadata` (no headers or bodies), `redacted` (headers and bodies with the [default masking](/getting-started/data-privacy#default-masking-patterns), 16 KB body cap) or `full` (the default). Every profile still sends the base record, so metrics and dashboards stay exact. For a first production rollout, start on `metadata`:

```python
app.add_middleware(
    ApiLensMiddleware,
    api_key=os.environ["APILENS_API_KEY"],
    app_id="orders-api",
    capture_profile="metadata",   # metadata | redacted | full
)
```

An explicit argument wins over the environment, so for a rollout leave the profile out of code and set `APILENS_CAPTURE_PROFILE` instead: the posture can then be widened or tightened with a redeploy. `metadata` still sends the URL with its query string, so add a `redact_query_params` pattern for any parameter that carries personal data. See [Capture profiles](/getting-started/data-privacy#capture-profiles) and [phase 2 of the rollout guide](/guides/third-party-rollout#phase-2-capture-posture).

## Environment variables

Every option has an `APILENS_*` variable of the same name, so keys, posture and patterns stay out of code. A typical deployment:

```bash
APILENS_API_KEY=apilens_...          # project key, from your secret store
APILENS_APP_ID=orders-api
APILENS_ENVIRONMENT=production
APILENS_CAPTURE_PROFILE=metadata     # metadata | redacted | full
APILENS_ANONYMIZE_IP=true            # truncate client IPs to /24 (IPv4), /48 (IPv6)
APILENS_REDACT_QUERY_PARAMS=^email$,token
# Kill switches. These win over code, in the direction that captures less:
# APILENS_CAPTURE_IP=false           # send no client IP
# APILENS_CAPTURE_SPANS=false        # no spans or error-trace logs
```

Precedence is **explicit argument > env var > default**. `APILENS_ENABLED=false` turns the SDK off on the next deploy, as long as `enabled` is not set in code ([SDK runbook](/guides/sdk-runbook#stop-capture-kill-switch)). The full list is in [Environment variables](/sdk-reference/python-configuration#environment-variables).

## Verify

Run the service, hit a few endpoints, and open your project's **Traffic** page — data appears within a few seconds. If nothing shows up, walk through [Troubleshooting](/support/troubleshooting).
