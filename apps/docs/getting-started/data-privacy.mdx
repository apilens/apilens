Observability tools see sensitive traffic, so this page is deliberately blunt about defaults. Where APILens captures something by default, we say so — and show you the switch.

## What is captured per request

| Data | Captured by default? | Control |
|---|---|---|
| Method, path template, status, response time | Yes | `enabled=False` disables everything |
| Request/response sizes, user agent | Yes | — |
| Client IP | Yes, in full | `capture_ip=False` / `APILENS_CAPTURE_IP=false` to drop it, `anonymize_ip=True` / `APILENS_ANONYMIZE_IP=true` to truncate it (IPv4 /24, IPv6 /48) |
| Request & response **headers** | Yes, with sensitive values redacted | `capture_headers=False`, plus `redact_headers=[…]` for your own patterns |
| Request & response **bodies** | Yes, truncated at 64 KB | `capture_payloads=False`, `log_request_body` / `log_response_body` individually, or field-level `redact_body_fields=[…]` |
| **Query strings** | Yes, as part of the exact request URL, with [default patterns](#default-masking-patterns) masked | `redact_query_params=[…]` per-parameter |
| Entire requests to matching paths / user agents | Yes, unless excluded; [health checks and probes](#default-exclusions) are excluded by default | `exclude_paths=[…]` / `exclude_user_agents=[…]` regexes, `APILENS_EXCLUDE_PATHS` / `APILENS_EXCLUDE_USER_AGENTS`, `default_exclusions=False` to record probes |
| Consumer identity | **No** — only what you explicitly set | `set_consumer(...)` |
| Trace spans | Yes (timing + endpoint/URL names, no payloads) | `capture_spans=False` or `APILENS_CAPTURE_SPANS=false` |
| Error stack traces | Yes, on unhandled exception or 5xx | disabled along with spans |

<Warning>
Unlike some tools that ship with request logging off, APILens captures headers and bodies **by default** so the request log is useful from minute one. If your API handles regulated data, decide deliberately: keep it, scope it down, or turn it off before deploying.
</Warning>

## Automatic header redaction

Values of these headers are replaced with `[redacted]` before leaving your process:

`authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `api-key`, `x-auth-token`, `x-amz-security-token`, `x-csrf-token`

These built-ins always apply — you can only add to them (see [PII redaction](#pii-redaction-query-params-headers-body-fields) below), never remove them. Serialized headers are additionally capped at 8 KB per side, dropping the longest values first.

## Default masking patterns

On top of the exact header names above, the SDK ships regex patterns that are **always on** — no configuration needed. Each is matched case-insensitively (`re.search`) against the query parameter, header, or JSON body field **name**, and a matching value is stored as `[redacted]`:

| Applies to | Built-in patterns |
|---|---|
| Query params (`DEFAULT_MASK_QUERY_PARAMS`) | `auth`, `api.?key`, `secret`, `token`, `password`, `pwd` |
| Headers (`DEFAULT_MASK_HEADER_PATTERNS`) | `auth`, `api.?key`, `secret`, `token`, `cookie` |
| JSON body fields (`DEFAULT_MASK_BODY_FIELDS`) | `password`, `pwd`, `token`, `secret`, `auth`, `card.?number`, `ccv`, `cvv`, `cvc`, `ssn` |

So a request to `/search?token=abc&q=shoes` is stored as `/search?token=[redacted]&q=shoes` with no config at all. Patterns are unanchored, so `token` also covers `access_token` and `auth` covers `x-auth-user`.

- **Body masking covers strings and numbers.** `{"card_number": 4242424242424242}` is masked just like `{"card_number": "4242…"}`. A nested object or array under a matching name is masked whole; booleans and `null` stay visible.
- **Unchanged when nothing matches.** A query string or body with no matching name is passed through byte-for-byte.
- **Your patterns extend these, never replace them.** `redact_query_params`, `redact_headers` and `redact_body_fields` below are added to the defaults.
- **Compiled once.** Defaults and your patterns are compiled into one regex per category when the middleware is created; nothing is compiled per request. An invalid pattern raises at startup.

## PII redaction: query params, headers, body fields

Beyond the built-in header list and default patterns, you can redact **more values by name** — query parameters, extra headers, and JSON body fields — with three middleware options:

```python
app.add_middleware(
    ApiLensMiddleware,
    api_key="apilens_xxx",
    app_id="orders-api",
    # Regexes matched case-insensitively against NAMES; matched VALUES
    # are stored as [redacted]. Anchor for exact matches.
    redact_query_params=[r"^card_number$", r"token"],
    redact_headers=[r"^x-internal-secret$"],        # on top of the built-ins
    redact_body_fields=[r"^password$", r"^cvv$", r"card"],
)
```

How it behaves:

- **Matching is by name, not value.** Each pattern is matched case-insensitively (`re.search`) against the query parameter name, header name, or JSON field name. Use `^…$` anchors for exact matches — an unanchored `token` also matches `access_token`.
- **Values become `[redacted]`, names stay visible.** The request log still shows *what* was sent (`/charge?access_token=[redacted]&promo=SAVE10`), never the sensitive value.
- **Body redaction walks nested JSON** — objects inside objects, objects inside arrays. A body of `{"user": {"card_number": "4242…"}}` comes out as `{"user": {"card_number": "[redacted]"}}`. Non-JSON bodies pass through unchanged; use the capture switches if you log sensitive non-JSON payloads.
- **Redaction happens in the SDK, in your process.** The raw value never reaches APILens — same guarantee as the built-in header redaction.
- **It applies to both sides** — request *and* response headers and bodies.

In Django the same three options are settings:

```python
APILENS_REDACT_QUERY_PARAMS = [r"^card_number$", r"token"]
APILENS_REDACT_HEADERS = [r"^x-internal-secret$"]
APILENS_REDACT_BODY_FIELDS = [r"^password$", r"^cvv$", r"card"]
```

<Note>
Redaction applies to values captured going forward — it cannot retroactively scrub requests that were already recorded without it. Configure it **before** pointing production traffic at APILens.
</Note>

## Masking error-trace logs: `mask_log_record`

When a request raises or returns a 5xx, the SDK sends an `ERROR` log record (message plus stack trace) correlated to the request's trace. Messages and stack traces can contain secrets, so every log record goes through two steps before it is queued:

1. **Your `mask_log_record(record)` callback**, if set. It receives the `LogRecord` and returns it (edited or replaced) to send it, or `None` to drop it.
2. **Built-in `key=value` masking**, always on. In the message, the stack-trace payload and attribute values, any `name=value`, `name: value` or `'name': 'value'` pair whose name matches a default sensitive pattern (every query, header and body pattern in the table above) has its value replaced with `[redacted]`. `token=abc` becomes `token=[redacted]`, and `Authorization: Bearer abc` becomes `Authorization: [redacted]`. Attributes whose key matches are masked whole.

```python
import re
from apilens import ApiLensClient, ApiLensConfig, LogRecord

EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")

def mask_log_record(record: LogRecord) -> LogRecord | None:
    if record.endpoint_path.startswith("/admin/"):
        return None                                   # drop the record entirely
    record.message = EMAIL.sub("<email>", record.message)
    record.payload = EMAIL.sub("<email>", record.payload)
    return record

client = ApiLensClient(ApiLensConfig(api_key="apilens_xxx", mask_log_record=mask_log_record))
app.add_middleware(ApiLensMiddleware, client=client, app_id="orders-api")
```

- **The callback runs first and cannot turn the built-ins off.** If it puts a `token=…` back into the message, that value is still masked.
- **Fail closed.** If the callback raises, or returns anything other than a `LogRecord` or `None`, the record is dropped. It is never sent unmasked.
- **It covers every log record**: the automatic error-trace logs today, and any application logs the SDK sends in future.

In Django, set `APILENS_MASK_LOG_RECORD` to the callable or its dotted import path (`"myapp.apilens.mask_log_record"`). An import path that cannot be resolved raises at startup.

## Client IP: `capture_ip` and `anonymize_ip`

The client IP is taken from the first `X-Forwarded-For` entry, then `X-Real-IP`, then the socket peer. Two options control what is sent, both applied in your process before the record is built:

| Option | Env var | Django setting | Effect |
|---|---|---|---|
| `capture_ip=False` | `APILENS_CAPTURE_IP=false` | `APILENS_CAPTURE_IP = False` | No IP is sent at all. Wins over `anonymize_ip`. |
| `anonymize_ip=True` | `APILENS_ANONYMIZE_IP=true` | `APILENS_ANONYMIZE_IP = True` | IPv4 keeps its /24 (`203.0.113.42` → `203.0.113.0`); IPv6 keeps its /48 (`2001:db8:85a3:8d3::1` → `2001:db8:85a3::`). IPv4-mapped IPv6 is treated as IPv4. A value that is not a valid IP is dropped rather than sent. |

Both are client options, so they cover every framework integration:

```python
from apilens import ApiLensClient, ApiLensConfig

client = ApiLensClient(ApiLensConfig(api_key="apilens_xxx", anonymize_ip=True))
```

With the one-line `ApiLensMiddleware` (which builds its own client), use the env vars. As with the other privacy switches, the env vars can only tighten capture: `APILENS_CAPTURE_IP=false` beats `capture_ip=True` in code, never the other way round.

<Note>
**Limitation:** an anonymised IP is a network, not a client. All callers in the same /24 (IPv4) or /48 (IPv6) show up as **one** IP in the consumer and IP filters and are counted together, so per-IP breakdowns become per-network breakdowns. Requests recorded before you turned anonymisation on keep their full IP, so the same caller can appear under both values for a while.
</Note>

## Excluding paths (health checks, probes)

Some endpoints should never be recorded at all — load-balancer health checks, readiness probes, metrics scrapes. Pass `exclude_paths` and matching requests bypass the SDK entirely: no request record, no span, no error log, and no body buffering.

```python
app.add_middleware(
    ApiLensMiddleware,
    api_key="apilens_xxx",
    app_id="orders-api",
    exclude_paths=[r"^/health$", r"^/ready$", r"^/metrics"],
)
```

- **Matched against the actual path**, not the route template, case-insensitively (`re.search`), with the query string removed. `^`/`$` anchor to the path: `r"^/metrics$"` skips `/metrics` and `/metrics?probe=1` but not `/metrics/cpu` or `/api/metrics`.
- **Compiled once at startup.** An invalid regex raises when the middleware is constructed, not on the first request.
- **Django:** `APILENS_EXCLUDE_PATHS = [r"^/health$", r"^/ready$"]` (a comma-separated string also works).
- **Environment variable:** `APILENS_EXCLUDE_PATHS="^/health$,^/ready$"` adds patterns on top of the ones in code, for every framework. Because it is split on commas, put any regex that needs a literal comma (`{1,3}`) in code instead.
- **User agents:** `exclude_user_agents=[r"^uptimerobot"]` (Django `APILENS_EXCLUDE_USER_AGENTS`, env var `APILENS_EXCLUDE_USER_AGENTS`) skips requests whose `User-Agent` header matches, with the same case-insensitive `re.search` semantics.

### Default exclusions

Health checks, probes and browser housekeeping files are excluded out of the box, before your `exclude_paths` are checked. The built-in lists (`DEFAULT_EXCLUDED_PATHS` and `DEFAULT_EXCLUDED_USER_AGENTS` in `apilens/client/_exclusions.py`), all case-insensitive:

| Paths | User agents |
|---|---|
| `/_?healthz?$` | `health[\-_ ]?check` |
| `/_?health[\-_]?checks?$` | `microsoft-azure-application-lb` |
| `/_?heart[\-_]?beats?$` | `googlehc` |
| `/ping$` | `kube-probe` |
| `/ready$` | |
| `/live$` | |
| `/favicon(?:-[\w-]+)?\.(?:ico\|png\|svg)$` | |
| `/apple-touch-icon(?:-[\w-]+)?\.png$` | |
| `/robots\.txt$` | |
| `/sitemap\.xml$` | |
| `/manifest\.json$` | |
| `/site\.webmanifest$` | |
| `/service-worker\.js$` | |
| `/sw\.js$` | |
| `/\.well-known/` | |

That covers `/health`, `/healthz`, `/health_checks`, `/heartbeat`, `/ping`, `/ready`, `/live`, favicon, robots, sitemap, manifest and service-worker files, anything under `/.well-known/`, and the Kubernetes, Google Cloud, Azure and generic health-check probe user agents. To record them, pass `default_exclusions=False` (Django: `APILENS_DEFAULT_EXCLUSIONS = False`); your own `exclude_paths` and `exclude_user_agents` still apply.

## Turning capture down (or off)

```python
app.add_middleware(
    ApiLensMiddleware,
    api_key="apilens_xxx",
    app_id="orders-api",
    enable_request_logging=False,   # no headers, no bodies
    # or, more surgical:
    log_request_body=False,
    log_response_body=False,
    capture_headers=False,
    max_payload_bytes=4096,         # keep bodies but cap them tighter (0 = none)
)
```

These environment variables act as deploy-time kill switches, overriding code:

- `APILENS_CAPTURE_SPANS=false` — stop all span and error-trace capture
- `APILENS_PARAMETRIZE_PATHS=false` — disable heuristic path templating
- `APILENS_CAPTURE_IP=false` — stop sending client IPs
- `APILENS_ANONYMIZE_IP=true` — truncate client IPs (IPv4 /24, IPv6 /48)

## What APILens never does

- **Never reads or infers identity.** No decoding of `Authorization` headers, JWTs, or sessions. The Consumers page shows only what your code passes to `set_consumer()`.
- **Never blocks or breaks a request.** Telemetry failures are retried and then dropped silently; nothing propagates into your handlers.
- **Never traces its own traffic.** The SDK's calls to the ingest endpoints are excluded from spans.

## What's still missing

Callback-based masking — a custom function deciding per request whether to drop a whole body (e.g. everything under `/admin/`) — is **not available yet**; it's on the [roadmap](/roadmap). The regex options above plus the capture switches cover everything else.

<Note>
Data is stored in ClickHouse (telemetry) and Postgres (metadata) operated by APILens. If you need data to stay entirely on your infrastructure, point `base_url` at a self-hosted ingest service — see the [Ingest API](/ingest/ingest-api).
</Note>
