Observability tools see sensitive traffic, so this page is deliberately blunt about defaults. Where APILens captures something by default, we say so and show you the switch. It covers the Python (`apilenss`), TypeScript (`apilens-js-sdk`) and Java (`apilens-java-sdk`) SDKs; where an SDK lacks an option, the tables say so.

## Two lines of defence

A sensitive value has to get past two independent filters before it is stored:

1. **The SDK, in your process.** Built-in masking, your own patterns, mask callbacks, exclusions, sampling and the capture switches all run before a record is queued. A value the SDK masks never leaves your process and never sits in its in-memory queue.
2. **The ingest edge, on the server.** Before a record is written to ClickHouse, the edge applies the same built-in masking again, plus your project's and app's [server-side privacy policy](#server-side-privacy-policy), and enforces [payload and header caps](#server-side-caps). An old SDK, a misconfigured SDK, or a hand-rolled client posting to the [Ingest API](/ingest/ingest-api) cannot store more than the policy allows.

The two lines use the same built-in lists, so a pattern you add on the server catches what an SDK config missed, without a redeploy. Neither line can remove the built-ins.

## What is captured per request

| Data | Captured by default? | Python | TypeScript | Java (`apilens.*` property) |
|---|---|---|---|---|
| Method, route template, status, latency | Yes | `enabled=False` stops everything | `enabled: false` | `enabled=false` |
| Request/response sizes, user agent, trace id | Yes | — | — | — |
| Client IP | Yes, in full | `capture_ip=False`, `anonymize_ip=True` ([details](#client-ip)) | Not available: always sent in full | `capture-ip=false`, `anonymize-ip=true` |
| Request & response **headers** | Yes, [sensitive values masked](#automatic-header-redaction), 8 KB cap | `capture_headers=False`, `redact_headers=[…]` | `requestLogging.captureHeaders: false`, `redactHeaders` | `capture-headers=false`, `redact-headers` |
| Request & response **bodies** | JSON, text and form-encoded only, [masked](#default-masking-patterns); [other types](#which-bodies-are-captured) become a size placeholder | `capture_payloads=False`, `log_request_body` / `log_response_body`, `redact_body_fields`, `mask_request_body` / `mask_response_body` | `requestLogging.capturePayloads`, `logRequestBody` / `logResponseBody`, `redactBodyFields`, `maskRequestBody` / `maskResponseBody` | `capture-payloads`, `log-request-body` / `log-response-body`, `redact-body-fields`, `maskRequestBody` / `maskResponseBody` |
| Body size cap | 64 KB (Python, Java), 8 KB (TypeScript) | `max_payload_bytes` (`0` = no bodies) | `requestLogging.maxPayloadBytes` | `max-payload-bytes` |
| **Query string** (on `raw_path`) | Yes, [default patterns](#default-masking-patterns) masked | `redact_query_params=[…]` | `redactQueryParams` | `redact-query-params` |
| **Validation errors** (400/422 field errors: `loc`, `msg`, `type`) | Yes (Python: FastAPI, Litestar, Django Ninja) | `capture_validation_errors=False` | Not captured | Not captured |
| Health checks, probes, static housekeeping files | **No**, [excluded by default](#default-exclusions) | `default_exclusions=False` to record them | `defaultExclusions: false` | `default-exclusions=false` |
| Requests to your own paths / user agents | Yes, unless excluded | `exclude_paths`, `exclude_user_agents` | `excludePaths`, `excludeUserAgents` | `exclude-paths`, `exclude-user-agents` |
| Detail (headers, bodies, spans, error log) | Yes, for 100% of requests | `sample_rate`, `sample_on_request`, `sample_on_response` | `sampleRate`, `sampleOnRequest`, `sampleOnResponse` | `sample-rate`, `sampleOnRequest`, `sampleOnResponse` |
| Consumer identity | **No**, only what you set | `set_consumer(...)` | `setConsumer(req, …)` | `ApiLensConsumerResolver` bean |
| Custom request attributes | **No**, only what you set (sent on the record and span; keep secrets out of them) | `set_request_attribute(key, value)` | Not available | Not available |
| Trace spans (timing and endpoint/URL names, no payloads) | Yes | `capture_spans=False` | `captureSpans: false` | `capture-spans=false` |
| Error log (message and stack trace on an unhandled exception or 5xx) | Yes | Off with spans; [`mask_log_record`](#masking-error-trace-logs) | Off with spans | Off with spans |

Every option also has an `APILENS_*` environment variable with the same name in all three SDKs (`APILENS_CAPTURE_HEADERS`, `APILENS_REDACT_BODY_FIELDS`, `APILENS_SAMPLE_RATE`, …). Django reads the same names as settings. See [deploy-time kill switches](#deploy-time-kill-switches).

<Warning>
Unlike some tools that ship with request logging off, APILens captures headers and bodies **by default** so the request log is useful from minute one. If your API handles regulated data, decide deliberately: keep it, scope it down, or turn it off before deploying. The quickest way is a [capture profile](#capture-profiles).
</Warning>

## Capture profiles

`capture_profile` (TypeScript and Java: `captureProfile`, Spring `apilens.capture-profile`) picks a whole capture posture in one word, so the choice is explicit and greppable in your config. It sets the defaults of the capture flags; any flag you set explicitly (in code, its own `APILENS_*` env var, Django setting or Spring property) wins over the preset.

| Profile | Headers | Request / response bodies | Validation errors (Python) | Body cap |
|---|---|---|---|---|
| `metadata` | Off | Off | Off | — |
| `redacted` | On, [sensitive headers](#automatic-header-redaction) masked | On, [default patterns](#default-masking-patterns) masked | On | 16 KB |
| `full` (default) | On, [sensitive headers](#automatic-header-redaction) masked | On, [default patterns](#default-masking-patterns) masked | On | 64 KB (TypeScript: `maxPayloadBytes`, 8 KB) |

Every profile still sends the base record (method, route, status, latency, sizes, consumer, IP, user agent, trace id), so dashboards and metrics stay exact. The built-in masking patterns apply under every profile.

<Tip>
**Recommended first production rollout: `metadata`.** The SDK default stays `full` for backwards compatibility. Start with `metadata`, check the request log, then move to `redacted` once you know what your payloads contain.
</Tip>

<CodeGroup>
```python Python
app.add_middleware(
    ApiLensMiddleware,
    api_key=os.environ["APILENS_API_KEY"],
    app_id="orders-api",
    capture_profile="metadata",   # metadata | redacted | full
)
```

```js TypeScript
useApiLens(app, {
  apiKey: process.env.APILENS_API_KEY,
  captureProfile: "metadata",
});
```

```properties Java (Spring Boot)
apilens.capture-profile=metadata
```
</CodeGroup>

- **Env var:** `APILENS_CAPTURE_PROFILE=metadata` in every SDK. Django: `APILENS_CAPTURE_PROFILE = "metadata"`.
- **Precedence:** explicit flag > the flag's env var / Django setting / Spring property > profile > default. `capture_profile="metadata", log_response_body=True` keeps response bodies only.
- **Validated at startup.** An unknown profile name raises when the middleware or filter is created.

## Automatic header redaction

In every SDK, values of these headers are replaced with `[redacted]` before leaving your process:

`authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `api-key`, `x-auth-token`, `x-amz-security-token`, `x-csrf-token`

These built-ins always apply: you can add to them, never remove them. The ingest edge strips the same headers again whatever the SDK sent. Serialized headers are capped at 8 KB per side, dropping the longest values first.

## Default masking patterns

On top of the exact header names above, the three SDKs and the ingest edge share the same regex lists, **always on**, no configuration needed. Each pattern is matched case-insensitively anywhere in the query parameter, header or JSON body field **name**, and a matching value is stored as `[redacted]`:

| Applies to | Built-in patterns |
|---|---|
| Query params (`DEFAULT_MASK_QUERY_PARAMS`) | `auth`, `api.?key`, `secret`, `token`, `password`, `pwd` |
| Headers (`DEFAULT_MASK_HEADER_PATTERNS`) | `auth`, `api.?key`, `secret`, `token`, `cookie` |
| JSON body fields, at any depth (`DEFAULT_MASK_BODY_FIELDS`) | `password`, `pwd`, `token`, `secret`, `auth`, `card.?number`, `ccv`, `cvv`, `cvc`, `ssn` |

So a request to `/search?token=abc&q=shoes` is stored as `/search?token=[redacted]&q=shoes` with no config at all. Patterns are unanchored, so `token` also covers `access_token` and `auth` covers `x-auth-user`.

- **Body masking covers strings and numbers.** `{"card_number": 4242424242424242}` is masked just like `{"card_number": "4242…"}`. In the SDKs a nested object or array under a matching name is masked whole; booleans and `null` stay visible.
- **Unchanged when nothing matches.** A query string or body with no matching name is passed through byte for byte.
- **Your patterns extend these, never replace them.**
- **Compiled once.** Defaults and your patterns are compiled when the middleware or filter is created, never per request. An invalid pattern fails at startup.

## Your own masking patterns

Add patterns for query parameters, headers and JSON body fields. They work like the defaults: matched against **names**, case-insensitively; matched **values** become `[redacted]`; names stay visible.

<CodeGroup>
```python Python
app.add_middleware(
    ApiLensMiddleware,
    api_key="apilens_xxx",
    app_id="orders-api",
    redact_query_params=[r"^card_number$", r"token"],
    redact_headers=[r"^x-internal-secret$"],
    redact_body_fields=[r"^password$", r"^cvv$", r"card"],
)
```

```python Django
APILENS_REDACT_QUERY_PARAMS = [r"^card_number$", r"token"]
APILENS_REDACT_HEADERS = [r"^x-internal-secret$"]
APILENS_REDACT_BODY_FIELDS = [r"^password$", r"^cvv$", r"card"]
```

```js TypeScript
useApiLens(app, {
  apiKey: process.env.APILENS_API_KEY,
  redactQueryParams: ["^card_number$", "token"],
  redactHeaders: ["^x-internal-secret$"],
  redactBodyFields: [/^password$/, "^cvv$", "card"],
});
```

```properties Java (Spring Boot)
apilens.redact-query-params[0]=^card_number$
apilens.redact-headers[0]=^x-internal-secret$
apilens.redact-body-fields[0]=^password$
apilens.redact-body-fields[1]=card
```
</CodeGroup>

Or, without a code change, in any SDK: `APILENS_REDACT_BODY_FIELDS=^password$,^ssn$` (comma-separated; put a regex that needs a literal comma in code instead).

- **Use `^…$` anchors for exact matches.** An unanchored `token` also matches `access_token`.
- **Body redaction walks nested JSON**: objects inside objects, objects inside arrays. `{"user": {"card_number": "4242…"}}` comes out as `{"user": {"card_number": "[redacted]"}}`.
- **It applies to both sides**: request *and* response headers and bodies.
- **Redaction happens in the SDK, in your process.** The raw value never reaches APILens.

<Note>
Masking applies to records captured going forward. It cannot scrub requests that were already stored without it (they age out with [retention](#retention)). Configure it **before** pointing production traffic at APILens.
</Note>

## Which bodies are captured

Bodies are captured by **content type**, read from the `Content-Type` header of each side. All three SDKs share the default list:

| Content type | What is stored |
|---|---|
| `application/json`, any `application/*+json` (`problem+json`, `vnd.api+json`, …) | The body, with [JSON field masking](#default-masking-patterns) |
| `text/*` (`text/plain`, `text/html`, `text/csv`, …) | The body as text |
| `application/x-www-form-urlencoded` | The body, with each field masked like a query parameter: a field whose name matches a body-field **or** query-parameter pattern is stored as `[redacted]`, so `user=ada&password=x` becomes `user=ada&password=[redacted]` |
| Anything else: `multipart/form-data` uploads, images, PDFs, archives, `application/octet-stream`, or no `Content-Type` at all | A placeholder such as `[multipart/form-data, 48213 bytes omitted]`. The body is never buffered or read, so large uploads and downloads cost nothing. |

- **Parameters are ignored** (`application/json; charset=utf-8` counts as `application/json`), and matching is case-insensitive.
- **Change the list** with `capture_content_types` (Python; Django `APILENS_CAPTURE_CONTENT_TYPES`) or `captureContentTypes` (TypeScript), or `APILENS_CAPTURE_CONTENT_TYPES` in either. It **replaces** the defaults, and entries are shell-style globs. **Java:** not available; the list above is fixed.

```python
app.add_middleware(
    ApiLensMiddleware,
    api_key="apilens_xxx",
    app_id="orders-api",
    # Also capture XML; keep JSON and form bodies; stop capturing text/*.
    capture_content_types=[
        "application/json",
        "application/*+json",
        "application/x-www-form-urlencoded",
        "application/xml",
        "application/*+xml",
    ],
)
```

<Warning>
Adding a type such as `multipart/*` or `application/octet-stream` makes the SDK buffer those bodies (up to the body cap) and send them as text. Field masking only understands JSON and form-encoded bodies, so values inside other formats are sent unmasked unless a [mask callback](#body-mask-callbacks) handles them.
</Warning>

## Body mask callbacks

Field patterns match by name. For everything they can't express (XML, free text, card numbers inside a value, or "drop every body under `/kyc`"), give the SDK a callback that sees the captured raw body. All three SDKs have one per side:

| SDK | Request | Response | Body type |
|---|---|---|---|
| Python | `mask_request_body(info, body)` | `mask_response_body(info, body)` | `bytes` |
| TypeScript | `maskRequestBody(info, body)` | `maskResponseBody(info, body)` | `Buffer` |
| Java | `maskRequestBody((info, body) -> …)` | `maskResponseBody((info, body) -> …)` | `byte[]` |

The request info carries `method`, `path`, `raw_path` (query already redacted), `headers` and `content_type`; the response info carries `request`, `status_code`, `headers` and `content_type` (camelCase in TypeScript and Java).

<CodeGroup>
```python Python
def mask_request_body(info, body: bytes) -> bytes | None:
    if info.path.startswith("/kyc"):
        return None  # stored as [masked]
    return body

app.add_middleware(ApiLensMiddleware, api_key="apilens_xxx", app_id="orders-api",
                   mask_request_body=mask_request_body)
# Django: APILENS_MASK_REQUEST_BODY = "myapp.apilens.mask_request_body"
```

```js TypeScript
useApiLens(app, {
  apiKey: process.env.APILENS_API_KEY,
  maskRequestBody: (info, body) => (info.path.startsWith("/kyc") ? null : body),
  maskResponseBody: (info, body) =>
    Buffer.from(body.toString().replace(/\d{12,19}/g, "####")),
});
```

```java Java
@Bean
ApiLensSpringOptionsCustomizer apiLensBodyMasking() {
  return options -> options
      .maskRequestBody((info, body) -> info.path().startsWith("/kyc") ? null : body);
}
```
</CodeGroup>

- **Order is fixed:** callback first, then your regex field patterns, then the built-in defaults. The built-ins still apply to whatever the callback returns, so it cannot switch them off.
- **Return the bytes to store, or `null` / `None`** to store the whole body as `[masked]`.
- **Fail closed.** If the callback throws, or returns something that is not bytes (a `Promise` included, in TypeScript), the body is stored as `[masked]`, never raw.
- **Only captured bodies are passed.** Callbacks are not called for an omitted body (wrong content type, sampled out, capture off), and they receive the body already truncated to the body cap.

## Masking error-trace logs

When a request raises or returns a 5xx, the SDK sends an `ERROR` log record (message plus stack trace) correlated to the request's trace. Messages and stack traces can contain secrets.

- **All SDKs:** the ingest edge masks every log record before it is stored. Any `name=value`, `name: value` or `'name': 'value'` pair in the message whose name matches a built-in or [policy](#server-side-privacy-policy) pattern has its value replaced, and JSON fields in the payload are masked like a body.
- **Python only:** `mask_log_record` lets you edit or drop a record in your process, and the same built-in `key=value` masking then runs in the SDK too. TypeScript and Java do not have this callback; turn the error log off with `captureSpans: false` / `apilens.capture-spans=false` if its content must not leave the process.

```python
import re
from apilens import ApiLensClient, ApiLensConfig, LogRecord

EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")

def mask_log_record(record: LogRecord) -> LogRecord | None:
    if record.endpoint_path.startswith("/admin/"):
        return None                                   # drop the record entirely
    record.message = EMAIL.sub("<email>", record.message)
    record.payload = EMAIL.sub("<email>", record.payload)
    return record

client = ApiLensClient(ApiLensConfig(api_key="apilens_xxx", mask_log_record=mask_log_record))
app.add_middleware(ApiLensMiddleware, client=client, app_id="orders-api")
```

- **The callback runs first and cannot turn the built-ins off.** If it puts a `token=…` back into the message, that value is still masked.
- **Fail closed.** If the callback raises, or returns anything other than a `LogRecord` or `None`, the record is dropped, never sent unmasked.
- **Django:** set `APILENS_MASK_LOG_RECORD` to the callable or its dotted import path. A path that cannot be resolved raises at startup.

## Client IP

The client IP is taken from the first `X-Forwarded-For` entry, then `X-Real-IP`, then the socket peer. Python and Java have two options, applied in your process before the record is built:

| Option | Python | Java | Env var | Effect |
|---|---|---|---|---|
| Drop the IP | `capture_ip=False` (Django `APILENS_CAPTURE_IP = False`) | `apilens.capture-ip=false` | `APILENS_CAPTURE_IP=false` | No IP is sent at all. Wins over anonymisation. |
| Anonymise the IP | `anonymize_ip=True` (Django `APILENS_ANONYMIZE_IP = True`) | `apilens.anonymize-ip=true` | `APILENS_ANONYMIZE_IP=true` | IPv4 keeps its /24 (`203.0.113.42` → `203.0.113.0`); IPv6 keeps its /48 (`2001:db8:85a3:8d3::1` → `2001:db8:85a3::`). IPv4-mapped IPv6 is treated as IPv4. A value that is not a valid IP is dropped rather than sent. |

**TypeScript:** not available yet; the SDK always sends the client IP in full.

In Python both are client options (`ApiLensConfig(anonymize_ip=True)`), so they cover every framework integration; with the one-line `ApiLensMiddleware`, use the env vars. Outside Spring, Java's `IpPrivacy.apply(ip, captureIp, anonymizeIp)` applies the same rule. The env vars can only tighten capture: `APILENS_CAPTURE_IP=false` beats `capture_ip=True` in code, never the other way round.

<Note>
**Limitation:** an anonymised IP is a network, not a client. All callers in the same /24 (IPv4) or /48 (IPv6) show up as **one** IP in the consumer and IP filters and are counted together. Requests recorded before you turned anonymisation on keep their full IP until they age out.
</Note>

### API key last-use IP

Separately from the requests your SDK captures, APILens keeps, per API key, the IP address and SDK version of the **last ingest request** made with that key (`last_used_ip`, `last_used_sdk`), so project members can review where a key is used. This IP is personal data about whoever runs the SDK: it is the address of the connection to the ingest service, overwritten at most every few minutes, and kept with the key. Self-hosted installs turn it off with `ingest.record_key_ip: false` (`APILENS_INGEST__RECORD_KEY_IP=false`); a stored IP is then cleared on the key's next use.

## Excluding requests

Some endpoints should never be recorded: load-balancer health checks, readiness probes, metrics scrapes. Matching requests bypass the SDK entirely: no record, no span, no error log, and no body buffering.

<CodeGroup>
```python Python
app.add_middleware(
    ApiLensMiddleware,
    api_key="apilens_xxx",
    app_id="orders-api",
    exclude_paths=[r"^/internal/", r"^/metrics"],
    exclude_user_agents=[r"^uptimerobot"],
)
```

```js TypeScript
useApiLens(app, {
  apiKey: process.env.APILENS_API_KEY,
  excludePaths: ["^/internal/", /^\/metrics/],
  excludeUserAgents: ["^uptimerobot"],
});
```

```properties Java (Spring Boot)
apilens.exclude-paths[0]=^/internal/
apilens.exclude-paths[1]=^/metrics
apilens.exclude-user-agents[0]=^uptimerobot
```
</CodeGroup>

- **Matched against the actual path**, not the route template, case-insensitively, with the query string removed. `^`/`$` anchor to the path: `^/metrics$` skips `/metrics` and `/metrics?probe=1` but not `/metrics/cpu`.
- **Compiled once at startup.** An invalid regex fails when the middleware or filter is created.
- **Environment variables** `APILENS_EXCLUDE_PATHS` and `APILENS_EXCLUDE_USER_AGENTS` (comma-separated) **add** patterns on top of the ones in code, in every SDK. Django reads the same names as settings.

### Default exclusions

Health checks, probes and browser housekeeping files are excluded out of the box, before your own patterns are checked. The three SDKs ship the same lists (`DEFAULT_EXCLUDED_PATHS` and `DEFAULT_EXCLUDED_USER_AGENTS`), all case-insensitive:

| Paths | User agents |
|---|---|
| `/_?healthz?$` | `health[\-_ ]?check` |
| `/_?health[\-_]?checks?$` | `microsoft-azure-application-lb` |
| `/_?heart[\-_]?beats?$` | `googlehc` |
| `/ping$` | `kube-probe` |
| `/ready$` | |
| `/live$` | |
| `/favicon(?:-[\w-]+)?\.(?:ico\|png\|svg)$` | |
| `/apple-touch-icon(?:-[\w-]+)?\.png$` | |
| `/robots\.txt$` | |
| `/sitemap\.xml$` | |
| `/manifest\.json$` | |
| `/site\.webmanifest$` | |
| `/service-worker\.js$` | |
| `/sw\.js$` | |
| `/\.well-known/` | |

That covers `/health`, `/healthz`, `/health_checks`, `/heartbeat`, `/ping`, `/ready`, `/live`, favicon, robots, sitemap, manifest and service-worker files, anything under `/.well-known/`, and the Kubernetes, Google Cloud, Azure and generic health-check probe user agents. To record them, turn the defaults off with `default_exclusions=False` (Django `APILENS_DEFAULT_EXCLUSIONS = False`), `defaultExclusions: false`, `apilens.default-exclusions=false` or `APILENS_DEFAULT_EXCLUSIONS=false`; your own patterns still apply.

## Sampling request detail

`sample_rate` / `sampleRate` (0.0–1.0, default `1.0`) keeps the request **detail** (headers, bodies, and in Python and Java the spans and error log) for that fraction of requests. **Sampling never changes metrics:** every request still sends its base record (method, path, status, latency, sizes, consumer, trace id) with `sampled=false`, so counts, error rates and latency percentiles stay exact. The bodies of sampled-out requests are never buffered.

Two callbacks refine the rate per request in every SDK: `sample_on_request` / `sampleOnRequest` before the handler runs, and `sample_on_response` / `sampleOnResponse` after the response, once the status, latency and consumer are known. The response callback can drop a kept request's detail but never bring back one the request stage dropped. A callback that throws is logged once and ignored.

```python
def sample(info):
    return info.status_code >= 400   # keep detail for failed requests only

app.add_middleware(ApiLensMiddleware, api_key="apilens_xxx", app_id="orders-api",
                   sample_rate=0.1, sample_on_response=sample)
```

See [Sampling](/sdk-reference/sampling) for every return value and the callbacks' fields.

## Remote capture policy

Each app has a capture policy you set in APILens, under **Settings → Capture** or with `PUT /api/v1/apps/{id}/capture-policy`. The SDKs receive it on their [heartbeat](/ingest/heartbeat) and apply it from the next request, within about two minutes and without a redeploy:

| Field | Effect |
|---|---|
| `enabled: false` | The SDKs stop sending records (heartbeats continue). The kill switch. |
| `sample_rate` | Samples out more requests; their base records are still sent. |
| `capture_headers`, `capture_request_body`, `capture_response_body` | `false` drops that part of the detail. |
| `max_payload_bytes` | Cuts bodies shorter. The edge also enforces it ([below](#server-side-caps)). |

The remote policy **only narrows** what is captured: a local setting that captures less always wins, and the policy never turns on what your code turned off. A failed heartbeat keeps the previous policy. An app without a saved policy captures everything its SDK config allows.

## Server-side privacy policy

The second line of defence. Each project, and each app within it, has a **deny list** applied by the ingest edge to every request and log record before it is stored, whatever SDK (or client) sent it. Set it under **Settings → Privacy** in the project, where a live tester shows what a sample value becomes, or with `PUT /api/v1/projects/{slug}/privacy-policy` (signed-in session; owners, admins and members):

```json
{
  "mask_query_params": ["^session$"],
  "mask_headers": ["^x-tenant-key$"],
  "mask_body_fields": ["^iban$", "^dob$"]
}
```

Add `?app=<slug>` to address one app's policy instead of the project-wide one. `GET` on the same path returns the policy and the built-in defaults.

- **What it masks:** query parameter values in `raw_path`, captured header values, JSON body field values (strings and numbers, at any depth) and `key=value` pairs in log messages, form-encoded bodies and other text bodies. Values become `[redacted]`; names stay visible.
- **What applies:** the built-in defaults (the [same lists](#default-masking-patterns) and [sensitive headers](#automatic-header-redaction) as the SDKs) **plus** the project's policy **plus** the record's app's policy. Policies only add patterns; nothing removes the defaults.
- **Patterns** are case-insensitive RE2 regexes matched against names, at most 50 per list and 256 bytes each. An invalid pattern is refused when you save, with the offending entry named.
- **Changes take effect** on the edges within the app cache TTL (`ingest.app_cache_ttl`, 60 s by default).
- **Fail closed.** If the edge cannot read a project's policy, it refuses the batch with `503` and `Retry-After` rather than store records without it; the SDKs retry.
- Masked records are counted in the app's [ingest health](/ingest/ingest-health) (`masked`), so you can see the edge catching what an SDK config missed.

### Server-side caps

The edge also caps what any client can store, after masking:

- Request and response **payloads** at the app's capture-policy `max_payload_bytes`, or 64 KB without one.
- Request and response **headers** at 8 KB per side.

A value cut by the edge ends with `…[truncated]` and is counted as `truncated` in [ingest health](/ingest/ingest-health).

## Deploy-time kill switches

Every option above can be set from the environment in all three SDKs, so tightening capture needs no code change (`APILENS_CAPTURE_PROFILE=metadata`, `APILENS_CAPTURE_HEADERS=false`, `APILENS_REDACT_BODY_FIELDS=…`). Most env vars lose to a value set explicitly in code; these act as kill switches and win over code, but only in the direction that captures less:

- `APILENS_CAPTURE_SPANS=false`: stop all span and error-trace capture
- `APILENS_CAPTURE_IP=false`: stop sending client IPs (Python, Java)
- `APILENS_ANONYMIZE_IP=true`: truncate client IPs to IPv4 /24, IPv6 /48 (Python, Java)
- `APILENS_PARAMETRIZE_PATHS=false`: disable heuristic path templating
- `APILENS_EXCLUDE_PATHS` / `APILENS_EXCLUDE_USER_AGENTS`: add exclusions on top of the ones in code

For a running fleet, the [remote capture policy](#remote-capture-policy) does the same from the dashboard.

## Retention

Telemetry is stored in ClickHouse and deleted automatically by table TTL; there is nothing to configure and no way to extend it per project.

| Data | Kept for |
|---|---|
| Request records (`api_requests`): headers, bodies, query strings, IPs, validation errors | **90 days** |
| Error-trace logs (`api_logs`) and trace spans (`api_spans`) | 30 days |
| Per-minute traffic rollups (`api_requests_1m`) | 30 days |
| Per-hour traffic rollups (`api_requests_1h`) and deploy markers (`api_deploys`): counts and latencies only, no payloads | 400 days |
| Consumer list (`api_consumers`): the ids and names your code passed to `set_consumer`, with first/last seen | No TTL |

Metadata (users, projects, apps, keys, policies) lives in Postgres. Requests recorded before you tightened capture or added a pattern keep what was captured until their 90 days run out.

## What APILens never does

- **Never reads or infers identity.** No decoding of `Authorization` headers, JWTs or sessions. The Consumers page shows only what your code passes to `set_consumer()`.
- **Never blocks or breaks a request.** Telemetry failures are retried and then dropped; nothing propagates into your handlers, and a throwing callback is contained.
- **Never traces its own traffic.** The SDKs' calls to the ingest endpoints are excluded from spans.

<Note>
If you need data to stay entirely on your infrastructure, run APILens yourself and point `base_url` / `baseUrl` / `apilens.base-url` at your own ingest. See the [Ingest API](/ingest/ingest-api).
</Note>
