Masking replaces sensitive **values** in captured request data with `[redacted]` (or a whole body with `[masked]`) while keeping the **names** visible, so the request log still shows what was sent. It runs in four layers inside the SDK, before a record is queued, and once more on the ingest edge before it is stored:

| Layer | What it masks | Python | TypeScript | Java |
|---|---|---|---|---|
| 1. [Built-in defaults](#built-in-defaults) | Query params, headers, JSON and form body fields by name | Always on | Always on | Always on |
| 2. [Your patterns](#your-own-patterns) | Same, with your regexes added | `redact_query_params`, `redact_headers`, `redact_body_fields` | `redactQueryParams`, `redactHeaders`, `redactBodyFields` | `redactQueryParams`, `redactHeaders`, `redactBodyFields` |
| 3. [Body callbacks](#body-mask-callbacks) | Anything in a captured body | `mask_request_body`, `mask_response_body` | `maskRequestBody`, `maskResponseBody` | `maskRequestBody`, `maskResponseBody` |
| 4. [Log-record callback](#log-record-callback) | Error-trace log message, stack trace, attributes | `mask_log_record` | Not available | Not available |
| Edge: [server-side policy](#server-side-policy) | Everything above, again, with the project's and app's patterns | Every SDK and client | | |

Which bodies reach layers 1 to 3 at all is decided first, by [content type](#content-types).

The examples on this page are taken from the SDK test suites (`packages/sdk-python/tests`, `packages/sdk-typescript/tests`, `packages/sdk-java/src/test`). Each one names the test it comes from, so you can run it.

## Order of operations

For each captured body the order is fixed, in all three SDKs:

1. **Content type.** A body whose type is not captured is never buffered and is stored as a placeholder. Nothing below runs.
2. **Body cap.** The body is cut to `max_payload_bytes` (`maxPayloadBytes`, `apilens.max-payload-bytes`).
3. **Your callback**, on the raw bytes.
4. **Your regex patterns and the built-in defaults**, on whatever the callback returned.

A callback can rewrite a body or drop it, but it can never switch layers 1 and 2 off: if it puts a `password` field back, that field is still masked. Query strings and headers go through layers 1 and 2 only.

## Built-in defaults

Always on, in every SDK and on the edge, and identical everywhere. Each pattern is a case-insensitive regex searched **anywhere** in the name, so `token` also covers `access_token` and `auth` covers `x-auth-user`.

| Applies to | Constant | Patterns |
|---|---|---|
| Query parameter names | `DEFAULT_MASK_QUERY_PARAMS` | `auth`, `api.?key`, `secret`, `token`, `password`, `pwd` |
| Header names | `DEFAULT_MASK_HEADER_PATTERNS` | `auth`, `api.?key`, `secret`, `token`, `cookie` |
| JSON body field names, at any depth | `DEFAULT_MASK_BODY_FIELDS` | `password`, `pwd`, `token`, `secret`, `auth`, `card.?number`, `ccv`, `cvv`, `cvc`, `ssn` |
| Header names, matched exactly | `SENSITIVE_HEADERS` | `authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `api-key`, `x-auth-token`, `x-amz-security-token`, `x-csrf-token` |

Form-encoded bodies (`application/x-www-form-urlencoded`) are masked field by field: a field is masked when its name matches a body-field **or** a query-parameter pattern.

How values are treated:

- **Strings and numbers are masked.** `{"cvv": 123}` is masked like `{"cvv": "123"}`, so numeric card numbers and PINs are caught.
- **A matching object or array is masked whole** in the SDKs: `{"auth": {"user": "u"}}` becomes `{"auth": "[redacted]"}`.
- **Booleans and `null` stay visible.** They carry no secret: `{"password_set": true}` is kept.
- **Nothing matches, nothing changes.** A query string or body with no matching name is passed through byte for byte, formatting included.
- **They cannot be removed.** Passing an empty list of your own patterns leaves every default in place.

## Your own patterns

Add regexes for query parameter, header and body field names. They **extend** the defaults, never replace them, and follow the same rules: case-insensitive, searched anywhere in the name, matched values become `[redacted]`. Body patterns walk nested JSON and apply to request and response alike.

| Python | TypeScript | Java (`apilens.*` property) | Env var (all SDKs) |
|---|---|---|---|
| `redact_query_params` | `redactQueryParams` | `redactQueryParams` (`redact-query-params`) | `APILENS_REDACT_QUERY_PARAMS` |
| `redact_headers` | `redactHeaders` | `redactHeaders` (`redact-headers`) | `APILENS_REDACT_HEADERS` |
| `redact_body_fields` | `redactBodyFields` | `redactBodyFields` (`redact-body-fields`) | `APILENS_REDACT_BODY_FIELDS` |

Env vars are comma-separated; a regex that needs a literal comma (`\d{1,3}`) goes in code or, in Java, in the indexed property form. Django reads the same names as settings (`APILENS_REDACT_BODY_FIELDS = [r"^email$"]`).

- **Anchor for exact names.** `token` matches `access_token`; `^token$` matches only `token`.
- **Compiled once.** Defaults and your patterns are compiled when the middleware or filter is created, never per request. An invalid regex fails there, at startup (Java: `PatternSyntaxException`).
- **Names, not values.** A pattern never looks inside a value. To catch a card number inside free text, use a [body callback](#body-mask-callbacks).

## Content types

A body is captured only if its `Content-Type` (each side read separately) is on the capture list. The default list is the same in all three SDKs (`DEFAULT_CAPTURE_CONTENT_TYPES`):

| Content type | Stored as |
|---|---|
| `application/json`, `application/*+json` | The body, with JSON field masking |
| `text/*` | The body as text. The SDKs apply no field masking to plain text; the [edge](#server-side-policy) masks `key=value` pairs in it. |
| `application/x-www-form-urlencoded` | The body, masked field by field |
| Anything else, or no `Content-Type` | A placeholder: `[multipart/form-data, 48213 bytes omitted]`, `[image/png, 50 bytes omitted]`, `[application/octet-stream, 7 bytes omitted]` |

A body that is not captured is **never buffered or read**, and the body callbacks are not called for it, so uploads and downloads cost nothing. Parameters are ignored (`application/json; charset=utf-8` is `application/json`) and matching is case-insensitive.

<Warning>
Opting a type in, such as `multipart/*` or `application/octet-stream`, makes the SDK buffer those bodies up to the body cap and send them as text. Field masking only understands JSON and form-encoded bodies, so values in any other format are sent unmasked unless a [body callback](#body-mask-callbacks) handles them.
</Warning>

## Body mask callbacks

For what name patterns cannot express: XML, free text, a card number inside a value, or "drop every body under `/kyc`". One callback per side receives the captured raw body and returns the bytes to store.

| | Python | TypeScript | Java |
|---|---|---|---|
| Request | `mask_request_body(info, body)` | `maskRequestBody(info, body)` | `maskRequestBody((info, body) -> …)` |
| Response | `mask_response_body(info, body)` | `maskResponseBody(info, body)` | `maskResponseBody((info, body) -> …)` |
| `body` | `bytes` | `Buffer` (a copy) | `byte[]` (a copy) |
| Return | `bytes` or `str` to store; `None` for `[masked]` | `Buffer`, `Uint8Array` or `string`; `null` / `undefined` for `[masked]` | `byte[]`; `null` for `[masked]` |
| Configured with | middleware kwarg; Django `APILENS_MASK_REQUEST_BODY` (callable or dotted path) | `useApiLens` option | `ApiLensSpringOptions.builder()`, or an `ApiLensSpringOptionsCustomizer` bean with Spring Boot |

What the callback is told:

| Field | Python | TypeScript | Java | Meaning |
|---|---|---|---|---|
| Method | `info.method` | `info.method` | `info.method()` | `POST` |
| Path | `info.path` | `info.path` | `info.path()` | Without the query string |
| Raw path | `info.raw_path` | `info.rawPath` | `info.rawPath()` | With the query string, sensitive values already `[redacted]` |
| Headers | `info.headers` | `info.headers` | `info.headers()` | Lower-cased names, **unredacted** (nothing has left your process yet) |
| Content type | `info.content_type` | `info.contentType` | `info.contentType()` | From the request (or response) headers |
| Response only | `info.request`, `info.status_code` | `info.request`, `info.statusCode` | `info.request()`, `info.statusCode()` | The request's info and the status |

Python's request info also carries `query`, `client_ip` and `attributes`, and its response info `route`, `response_time_ms`, the consumer fields and `sampled`.

- **Fail closed.** If the callback throws, or returns something that is not bytes (a number, an object, or in TypeScript a `Promise`), the body is stored as `[masked]`, never raw. The request itself is never affected.
- **Only captured bodies are passed.** Not called for an empty body, a body of a type that is not captured, a sampled-out request, or with body capture off.
- **Already truncated.** The callback receives at most the body cap, so a JSON body can arrive cut off and fail to parse. Return `None` / `null` if you cannot handle it.
- **Synchronous.** The callback runs on the request path; keep it fast.

## Log-record callback

When a request raises or returns a 5xx, the SDK sends an `ERROR` log record with the message and stack trace, correlated to the request's trace. Messages and stack traces can carry secrets.

<Tabs>
  <Tab title="Python">
    Built-in masking runs on every log record before it is queued: any `name=value`, `name: value` or `'name': 'value'` pair whose name matches a built-in query, header or body pattern has its value replaced, in the message, the payload (stack trace) and the attributes. From `tests/test_mask_log_record.py::test_mask_log_text_masks_default_sensitive_pairs`:

    | Message | Stored |
    |---|---|
    | `GET /x?access_token=abc&q=shoes` | `GET /x?access_token=[redacted]&q=shoes` |
    | `Authorization: Bearer eyJhbGci.x.y` | `Authorization: [redacted]` |
    | `{'password': 'hunter2', 'user': 'bob'}` | `{'password': '[redacted]', 'user': 'bob'}` |
    | `InvalidTokenError: signature expired (token=abc)` | `InvalidTokenError: signature expired (token=[redacted])` |

    `mask_log_record` is a client option that runs **before** the built-ins. Edit and return the record, return a new one, or return `None` to drop it. From `test_callback_can_edit_message_and_attributes` and `test_callback_returning_none_drops_the_record`:

    ```python
    from apilens import ApiLensClient, ApiLensConfig, LogRecord

    def mask(record: LogRecord) -> LogRecord | None:
        if "/admin" in record.endpoint_path:
            return None                                    # dropped, never sent
        record.message = record.message.replace("alice@example.com", "<email>")
        return record

    client = ApiLensClient(ApiLensConfig(api_key="apilens_xxx", mask_log_record=mask))
    app.add_middleware(ApiLensMiddleware, client=client, app_id="orders-api")
    ```

    - **The built-ins still run after it** (`test_builtins_run_after_the_callback`): a callback that returns a message of `token=leaked` sends `token=[redacted]`.
    - **Fail closed** (`test_failing_callback_drops_the_record`): if the callback raises or returns anything other than a `LogRecord` or `None`, the record is dropped.
    - **Django:** `APILENS_MASK_LOG_RECORD` is the callable or its dotted import path; a path that cannot be resolved raises at startup.
  </Tab>
  <Tab title="TypeScript">
    No log-record callback and no in-process log masking. The [edge](#server-side-policy) masks every log record before it is stored. If the error log must not leave your process at all, turn it off with `captureSpans: false` (or `APILENS_CAPTURE_SPANS=false`).
  </Tab>
  <Tab title="Java">
    No log-record callback and no in-process log masking. The [edge](#server-side-policy) masks every log record before it is stored. If the error log must not leave your process at all, turn it off with `apilens.capture-spans=false` (or `APILENS_CAPTURE_SPANS=false`).
  </Tab>

## Server-side policy

The ingest edge masks every request and log record again before writing it to ClickHouse, whichever SDK or client sent it. It applies the built-in defaults above, plus the project's policy, plus the record's app's policy, so a pattern added here catches what an SDK config missed without a redeploy.

Set it in the project under **Settings → Privacy**, or with the API (signed-in session; owners, admins and members):

```http
PUT /api/v1/projects/{slug}/privacy-policy
Content-Type: application/json

{
  "mask_query_params": ["^session$"],
  "mask_headers": ["^x-tenant-key$"],
  "mask_body_fields": ["^iban$", "^dob$"]
}
```

Add `?app=<slug>` for one app's policy. `GET` on the same path returns the policy and the built-in `defaults`. The response is the whole policy: a `PUT` replaces it, and an omitted list means none.

- **Patterns** are case-insensitive [RE2](https://github.com/google/re2/wiki/Syntax) regexes matched against names, at most 50 per list and 256 bytes each, trimmed and deduplicated. An invalid one is refused with `invalid_request` naming it. RE2 has no lookarounds or backreferences, so a pattern that works in an SDK may be refused here.
- **Changes apply** within the app cache TTL (`ingest.app_cache_ttl`, 60 s by default).
- **Fail closed.** If the edge cannot read a project's policy it answers `503` with `Retry-After` and the SDKs retry; it never stores a batch without the policy.
- **Counted.** Records the edge masked show as `masked` in [ingest health](/ingest/ingest-health).

The edge differs from the SDKs in three ways:

| | SDKs | Edge |
|---|---|---|
| Matching object or array in a JSON body | Masked whole | Walked: its string and number values are masked when their own names match |
| `text/*` bodies and non-JSON text | Left as is | `key=value` and `key: value` pairs masked, as in log messages |
| Log records | Python only (built-ins plus `mask_log_record`) | Always, with the policy's patterns too |

<Note>
Masking applies to records captured from then on. It does not rewrite what is already stored; that ages out with [retention](/getting-started/data-privacy#retention). Configure it before pointing production traffic at APILens.
</Note>
