The Python SDK splits configuration in two: **`ApiLensConfig`** controls the client (auth, delivery, resilience), and **middleware options** control what gets captured per request. Framework integrations pass both through.

```bash
pip install apilenss   # import as `apilens`
```

Current version: **0.4.0** · Python ≥ 3.10 · Only two runtime dependencies (`opentelemetry-api`, `opentelemetry-sdk`).

## ApiLensConfig (client)

```python
from apilens import ApiLensClient, ApiLensConfig

client = ApiLensClient(ApiLensConfig(api_key="apilens_xxx"))
```

| Option | Default | Description |
|---|---|---|
| `api_key` | — **(required)** | Project-level API key. Empty raises `ValueError`. |
| `project_slug` | `""` | Optional — the key already identifies the project; set it only to assert they match. |
| `base_url` | `"https://ingest.apilens.ai/v1"` | Ingest base URL. Point at your own host if self-hosting ingest. |
| `environment` | `"production"` | Environment label attached to every record. |
| `batch_size` | `200` | Records per batch; reaching it triggers an immediate flush. |
| `flush_interval` | `3.0` | Seconds between background flushes. |
| `mode` | `"thread"` | `"thread"`: a background thread flushes every `flush_interval`. `"inline"` (serverless): no thread; `client.flush()` sends synchronously and the ASGI/WSGI middlewares call it after each response is sent. Env `APILENS_MODE`. |
| `timeout` | `5.0` | Per-request HTTP timeout (seconds). |
| `verify_tls` | `True` | TLS certificate verification. |
| `ca_bundle_path` | `""` | Custom CA bundle for private CAs. |
| `max_queue_size` | `10_000` | Per-queue cap; oldest records are dropped when full. |
| `max_retries` | `3` | Delivery attempts per batch. |
| `retry_backoff_base` | `0.25` | Exponential backoff base (seconds). |
| `retry_backoff_max` | `5.0` | Backoff ceiling (seconds). |
| `enabled` | `True` | Master kill switch — `False` disables capture and the background worker. |
| `capture_ip` | `True` | `False` sends no client IP at all. See [Client IP](/getting-started/data-privacy#client-ip-capture_ip-and-anonymize_ip). |
| `anonymize_ip` | `False` | Truncate client IPs in-process: IPv4 to /24 (last octet zeroed), IPv6 to /48. |
| `ingest_path` / `spans_path` / `logs_path` | `"/requests"` / `"/traces"` / `"/logs"` | Endpoint paths, relative to `base_url`. |

## Middleware options (capture)

Accepted by `ApiLensMiddleware` (FastAPI), `instrument_app`/`instrument_flask`, `ApiLensPlugin` (Litestar), and the generic `ApiLensASGIMiddleware`/`ApiLensWSGIMiddleware`:

| Option | Default | Description |
|---|---|---|
| `app_id` | `""` | App slug — attributes traffic to an app in the project. **Required for tracing.** |
| `environment` | client's value | Per-app override of the environment label. |
| `enable_request_logging` | `True` | Master switch for header + body capture. |
| `log_request_body` | `True` | Capture request bodies. |
| `log_response_body` | `True` | Capture response bodies. |
| `capture_payloads` | `True` | AND-ed with `enable_request_logging` for bodies. |
| `capture_headers` | `True` | Capture headers (sensitive values redacted — see [Data privacy](/getting-started/data-privacy)). |
| `max_payload_bytes` | `65536` | Per-body truncation limit; `0` disables body capture. |
| `capture_content_types` | JSON, `+json`, `text/*`, form-encoded | Media-type globs whose bodies are captured; it replaces the defaults. Other bodies are stored as `[<content-type>, N bytes omitted]`. See [Data privacy](/getting-started/data-privacy#which-bodies-are-captured). |
| `redact_query_params` | `None` | Regexes matched against query parameter names; matched values stored as `[redacted]`. |
| `redact_headers` | `None` | Regexes matched against header names, on top of the built-in sensitive-header list. |
| `redact_body_fields` | `None` | Regexes matched against JSON body field names (recursive, request and response). |
| `capture_spans` | `True` | Automatic tracing + error-trace capture. |
| `service_name` | `""` | Span service name (defaults to the app id). |
| `get_consumer` | `None` | Centralized consumer resolver — see [Consumer identification](/sdk-reference/consumers). |
| `route_resolver` | `None` | Custom callback returning the route template for a request. |
| `parametrize_paths` | `True` | Heuristic path templating fallback — see [Path templating](/sdk-reference/path-templating). |
| `flush_on_shutdown` | `True` | Flush the queue on ASGI lifespan shutdown / process exit — see [Deployment shapes](#deployment-shapes). |
| `shutdown_timeout` | `5.0` | Upper bound, in seconds, on how long the shutdown flush may block. |

## Environment variables

Every capture, masking, sampling and exclusion option can be set from the
environment, on every framework, so a kill switch or a new redaction pattern
never needs a code change. Precedence: **explicit keyword argument > env var >
default**. Django reads the same names from settings first: a Django setting
wins over the env var, the env var over the default.

Booleans accept `1`/`0`/`true`/`false` (also `yes`/`no`/`on`/`off`, any case).
Lists are comma-separated (`APILENS_REDACT_BODY_FIELDS=^password$,^ssn$`); a
regex that needs a literal comma must be passed as a list in code. Unset or
empty variables are ignored; an unparseable value raises `ValueError` naming
the variable at startup. `apilens.client._env.load_env_config()` returns the
parsed values as a dict.

| Variable | Option | Type | Default |
|---|---|---|---|
| `APILENS_API_KEY` | `api_key` | string | — (required) |
| `APILENS_APP_ID` | `app_id` | string | `""` |
| `APILENS_ENVIRONMENT` | `environment` | string | `"production"` |
| `APILENS_BASE_URL` | `base_url` | string | `https://ingest.apilens.ai/v1` |
| `APILENS_ENABLED` | `enabled` | bool | `true` |
| `APILENS_CAPTURE_HEADERS` | `capture_headers` | bool | `true` |
| `APILENS_CAPTURE_PAYLOADS` | `capture_payloads` | bool | `true` |
| `APILENS_LOG_REQUEST_BODY` | `log_request_body` | bool | `true` |
| `APILENS_LOG_RESPONSE_BODY` | `log_response_body` | bool | `true` |
| `APILENS_MAX_PAYLOAD_BYTES` | `max_payload_bytes` | int | `65536` |
| `APILENS_CAPTURE_CONTENT_TYPES` | `capture_content_types` | list | JSON, `+json`, `text/*`, form-encoded |
| `APILENS_REDACT_QUERY_PARAMS` | `redact_query_params` | list | none |
| `APILENS_REDACT_HEADERS` | `redact_headers` | list | none |
| `APILENS_REDACT_BODY_FIELDS` | `redact_body_fields` | list | none |
| `APILENS_EXCLUDE_PATHS` | `exclude_paths` | list, **added to** the code value | none |
| `APILENS_EXCLUDE_USER_AGENTS` | `exclude_user_agents` | list, **added to** the code value | none |
| `APILENS_DEFAULT_EXCLUSIONS` | `default_exclusions` | bool | `true` |
| `APILENS_SAMPLE_RATE` | `sample_rate` | float 0.0–1.0 | `1.0` |
| `APILENS_CAPTURE_IP` | `capture_ip` | bool; `false` wins over code | `true` |
| `APILENS_ANONYMIZE_IP` | `anonymize_ip` | bool; `true` wins over code | `false` |
| `APILENS_CAPTURE_SPANS` | `capture_spans` | bool; `false` wins over code | `true` |
| `APILENS_BATCH_SIZE` | `batch_size` | int | `200` |
| `APILENS_FLUSH_INTERVAL` | `flush_interval` | float (seconds) | `3.0` |
| `APILENS_MODE` | `mode` | `thread` or `inline` | `thread` |

`APILENS_EXCLUDE_PATHS` / `APILENS_EXCLUDE_USER_AGENTS` add to the patterns
passed in code. `APILENS_CAPTURE_SPANS=false`, `APILENS_CAPTURE_IP=false` and
`APILENS_ANONYMIZE_IP=true` are kill switches: they win over code, but only in
the direction that captures less.

Other variables, outside this loader:

| Variable | Effect |
|---|---|
| `APILENS_PARAMETRIZE_PATHS` | `0`/`false`/`no`/`off` disables the heuristic templating fallback. |
| `APILENS_FLUSH_ON_SHUTDOWN` | `0`/`false`/`no`/`off` disables the automatic shutdown flush (lifespan and `atexit`). |
| `APILENS_SEND_METADATA` | `false` never sends the startup app metadata report. |
| `APILENS_PROXY` | Egress proxy for ingest traffic (`proxy_url`). |
| `APILENS_RELEASE` / `APILENS_COMMIT` | Deploy correlation stamped on every record. |

Django reads `APILENS_API_KEY`, `APILENS_APP_ID` (both required, from settings or the environment) and the optional set listed in the [Django guide](/setup-guides/django).

## Delivery semantics

Worth knowing when you reason about failure modes:

- Capture only **enqueues**; a single daemon thread (`apilens-flush`) does all network I/O.
- Three independent queues (requests, spans, logs) flush every `flush_interval` or as soon as `batch_size` accumulates.
- Retries use exponential backoff; 4xx responses other than 429 are not retried.
- On overflow the **oldest** record is dropped — your app's memory is bounded and never blocked.
- The framework integrations drain the queues on shutdown, bounded by `shutdown_timeout`; with a bare client, `client.shutdown(flush=True)` (or using the client as a context manager) does it.

## Deployment shapes

The SDK delivers from a background thread, so whatever is still queued when a
process exits is lost unless it is flushed first. The integrations do that for
you, once per client, bounded by `shutdown_timeout` (default **5 s**) so a slow
or unreachable ingest never holds up a deploy:

| Integration | Hook | Notes |
|---|---|---|
| FastAPI / Starlette / any ASGI app | ASGI `lifespan` shutdown event | Flushes after your own shutdown handlers and before the server is told shutdown is complete. `atexit` is registered too, for servers that run with lifespan off. |
| Django (WSGI or ASGI) | `atexit` | Django has no lifespan hook. `APILENS_FLUSH_ON_SHUTDOWN` / `APILENS_SHUTDOWN_TIMEOUT` settings. |
| Flask / any WSGI app | `atexit` | |

Each hook flushes at most once per client; if the deadline passes, the leftovers
are dropped and the process exits on time. Set `flush_on_shutdown=False` (or the
`APILENS_FLUSH_ON_SHUTDOWN=false` env var, which wins over code) to turn the hooks
off and call `client.shutdown(flush=True)` yourself.

**Multi-worker servers (gunicorn, uvicorn `--workers`, uwsgi).** Each worker
process has its own client and queue and flushes its own on exit. gunicorn sends
`SIGTERM` to workers on restart, `--max-requests` recycling and shutdown; a worker
that exits normally runs `atexit` (sync/gthread workers) or the lifespan shutdown
(`uvicorn.workers.UvicornWorker`). Keep gunicorn's `--graceful-timeout` (default
30 s) above `shutdown_timeout`, or the worker is `SIGKILL`ed mid-flush. Workers
killed by `SIGKILL`, the OOM killer or `--timeout` expiry run no hooks and lose
up to one `flush_interval` (3 s) of data. With uwsgi, enable `--enable-threads`
(the delivery thread needs it) and avoid `--skip-atexit`.

**Serverless (AWS Lambda, Cloud Run, Cloud Functions).** The runtime freezes or
kills the process between invocations, so a background thread may never run and
`atexit` / lifespan are not reliable. Set `mode="inline"` (or
`APILENS_MODE=inline`): no thread is started, the ASGI/WSGI middlewares deliver
each request's records synchronously right after its response is sent, and code
without a middleware calls `client.flush()` at the end of each invocation.
FastAPI on Lambda with Mangum:

```python
from fastapi import FastAPI
from mangum import Mangum
from apilens.fastapi import ApiLensMiddleware

app = FastAPI()
app.add_middleware(ApiLensMiddleware, api_key="apilens_xxx", app_id="orders-api", mode="inline")
handler = Mangum(app, lifespan="off")
```

Mangum returns the response to Lambda when the app returns, so on Lambda the
flush adds the ingest round-trip to the invocation. Keep `timeout` and
`max_retries` low. The Django middleware does not flush inline; call
`client.flush()` yourself (e.g. from a `request_finished` signal).

**CronJobs and scripts.** Use the client as a context manager
(`with ApiLensClient(...) as client:`) or call `client.shutdown(flush=True)` before
exit. In Kubernetes, `terminationGracePeriodSeconds` (default 30 s) must exceed
`shutdown_timeout` plus your app's own shutdown time.

## What's on the wire

Each request record carries: `app_id`, `timestamp`, `environment`, `method`, `path` (template), `raw_path` (exact URL including the query string, with any `redact_query_params` matches already redacted), `status_code`, `response_time_ms`, `request_size`, `response_size`, `ip_address` (proxy-header aware), `user_agent`, consumer fields, payloads/headers (as configured), `base_url`, `trace_id`, `span_id`. The full schema is in the [Ingest API reference](/ingest/request-schema).
